## Context

Core analytics dùng game definition, nhưng game allowlist/constraints/parser/jobs
chỉ có Lotto/Mega. Power có sáu main 1–55 và special lấy từ 49 số còn lại;
CSS nguồn lại giống Mega. MVP đã nghiệm thu cần giữ dữ liệu và bằng chứng cũ.

## Options

- Tạo pipeline/bảng/endpoint Power riêng: nhân bản logic và transaction policy.
- Mở rộng registry, constraints và source metadata: dùng lại use cases đã kiểm.

## Decision

Chọn mở rộng hiện có với ID `power_655`, flag domain special khác main.
Giữ cột `special_number`, canonical hash và schema response hiện có.
Checker/generator/analytics tiếp tục main-only; không tính thưởng vé hay bao.
Ingestion giữ source metadata trong adapter và kiểm URL/title/ID/number,
không suy game bằng CSS. Jackpot 2 có 5 main + special; parser hỗ trợ dấu `|`
của Power và `+` của Lotto theo game, kiểm chính xác điều kiện năm hạng Power.
Poll 19:30 thứ Ba/Năm/Bảy, reconcile 07:00 và startup catch-up dùng lock cũ.

## Consequences

Migration 0005 mở rộng năm CHECK game và CHECK số, giữ dữ liệu/prizes/hash/version.
Downgrade chỉ cho phép khi chưa có dữ liệu Power; có dữ liệu phải restore backup
thay vì tự xóa. Frontend nhận game từ API và hiển thị cả hai Jackpot.
Các mốc POWER được nghiệm thu riêng, không thay kết quả P8 lịch sử.

## Validation

POWER-01 đã kiểm consistency contract và nguồn. POWER-02..05 phải có domain/
parser/DB/API/analytics tests, migration DB trống và clone dữ liệu, frontend
gates/E2E desktop/mobile, backup/restore, full import/audit và collector lặp.
Kết quả thực tế ghi vào tài liệu nghiệm thu khi các kiểm chứng hoàn tất.
